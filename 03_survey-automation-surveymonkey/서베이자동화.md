## 2. 핵심 헬퍼 모듈 (sm_helper.py 사용법)

### 2.1 7개 질문 유형 (검증 완료)

| 헬퍼 | family / subtype | 용도 | 예시 |
|------|------------------|-----|------|
| `add_single()` | single_choice / vertical | 단일선택 | 성별, 연령대 |
| `add_multi()` | multiple_choice / vertical | 복수응답 | 관심사, 참여사업 |
| `add_matrix()` | matrix / single | 리커트 매트릭스 | TAM·IPA 만족도 |
| `add_short()` | open_ended / single | 짧은 주관식 | 휴대폰, 이메일 |
| `add_essay()` | open_ended / essay | 긴 주관식 | 자유의견 |
| `add_text()` | presentation / descriptive_text | 안내문 | 섹션 구분 |
| `new_page()` | (page) | 새 페이지 | 모듈 분기 |

### 2.2 required 타입 4가지 ★ 중요

```python
REQUIRED_ALL          # 단일선택·매트릭스 — 모든 행 응답 필수
REQUIRED_AT_LEAST_1   # 복수응답 — 최소 1개 이상
REQUIRED_EXACTLY_2    # 1·2순위 등 — 정확히 2개
REQUIRED_AT_MOST_3    # 최대 3개 (custom)
```

**중요**: SurveyMonkey API에서 `multiple_choice` 질문에 `required.type = "all"`을 적용하면 **모든 옵션을 다 선택해야** 진행됩니다 (사용자가 의도한 "필수 응답"이 아님). 복수응답은 반드시 `at_least 1` 사용.

### 2.3 IPA 매트릭스 분리 패턴 ★ 핵심

종이 설문에서 흔한 형태:
```
| 항목 | ←  만족도 (5점)  → | ← 중요도 (5점) → |
| 품질 | ① ② ③ ④ ⑤        | ① ② ③ ④ ⑤      |
```

이를 온라인에서는 **두 매트릭스로 분리**(같은 항목 순서):
```python
sb.add_matrix("Q15. [만족도] 평가", rows=ITEMS, choices=LIKERT5_SAT)
sb.add_matrix("Q15. [중요도] 평가", rows=ITEMS, choices=LIKERT5_IMP)
```

**왜?** SurveyMonkey 매트릭스는 한 표에 척도 1개만 가능. 강제로 12컬럼 표를 만들면 모바일에서 가독성 0.

## 3. Skip Logic (분기 로직) — API 미지원, UI 수동

⚠ **SurveyMonkey API v3는 Skip Logic을 지원하지 않습니다.** 공식 문서에 `display_logic`, `question_logic`, `branch_logic` 등 관련 필드가 없습니다.

### 3.1 UI에서 설정하는 방법

1. **Page Logic** (페이지 단위 분기):
   - 페이지 클릭 → 우측 ⋮ → **Page Logic**
   - "Show this page only if [Question] [is/contains] [Answer]"
2. **Question Logic** (질문 단위 분기):
   - 질문 우측 **Logic** 버튼
   - "If [Answer] is selected, skip to [Question/Page]"

### 3.2 자주 쓰는 분기 패턴

| 패턴 | UI 설정 |
|------|---------|
| 동의 거부 시 답례품 정보 건너뛰기 | Question Logic on 동의 질문 |
| 응답자 유형별 모듈 분기 | Page Logic on 모듈 페이지 |
| 1·2순위 정확히 2개 검증 | API에서 `exactly_2` 설정 (UI 불필요) |
| 특정 응답일 때만 후속 질문 표시 | Question Logic on 후속 질문 |

### 3.3 검증

UI 설정 후 반드시 **Preview** 모드에서 모든 분기 케이스를 1회 이상 시뮬레이션 검증.

## 5. 자주 쓰는 코드 스니펫

### 5.1 토큰 검증

```python
def verify_token(headers):
    r = requests.get("https://api.surveymonkey.com/v3/users/me", headers=headers)
    if r.status_code != 200:
        print(f"토큰 만료/무효: {r.status_code}")
        return False
    print(f"✓ 계정: {r.json().get('email')}")
    return True
```

### 5.2 설문 삭제

```python
def delete_survey(sid, headers):
    r = requests.delete(f"https://api.surveymonkey.com/v3/surveys/{sid}", headers=headers)
    return r.status_code in (200, 204)
```

### 5.3 모든 설문 목록 조회

```python
def list_surveys(headers):
    r = requests.get("https://api.surveymonkey.com/v3/surveys?per_page=100", headers=headers)
    return r.json().get("data", [])
```

### 5.4 응답 데이터 다운로드

```python
def get_responses(sid, headers):
    r = requests.get(f"https://api.surveymonkey.com/v3/surveys/{sid}/responses/bulk?per_page=100", headers=headers)
    return r.json().get("data", [])
```

## 6. 흔한 함정 (실제 경험 기반)

| 함정 | 증상 | 해결 |
|------|------|------|
| 매트릭스 subtype | `rating`으로 만들면 API 오류 | `single` 사용 (검증 완료) |
| 복수응답 required | `type=all`이면 모든 옵션 강제 | `type=at_least, amount=1` |
| Skip Logic API | 시도하면 400 에러 | UI에서만 설정 가능 |
| HTML 태그 | description에 `<table>` 사용 시 일부 환경에서 미렌더 | `<br>` `<strong>` 위주로 |
| 페이지 description 길이 | 너무 길면(2000자+) 잘림 | 안내문은 별도 add_text() 권장 |
| 동시 호출 | 100ms 간격으로 호출 시 rate limit | `time.sleep(0.25)` 사이사이 |
| 토큰 노출 | Git 커밋에 포함되면 즉시 무효화 | `.gitignore` 또는 환경변수 |
