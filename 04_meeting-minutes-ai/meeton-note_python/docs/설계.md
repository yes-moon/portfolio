# 미팅온 노트 (MeetOn Note) — 온프레미스 회의 녹음·전사·검색 데스크톱 앱 설계

> 작성 2026-09-06. [A대학교] 「[A시]교육발전특구사업 3년 종합성과보고서 및 교육혁신선도지역사업 계획서 작성 용역」 제안발표(9/7 14:00) 시연용.
> 미팅온(MeetOn, 저작권 접수 2026-08-30)의 회의록 생성·RAG 엔진을 **노트북 한 대 안에서, 인터넷 없이** 돌리는 단독 구성판.

## 1. 한 줄 정의
회의를 노트북 마이크로 녹음하면 → 로컬 STT가 텍스트로 만들고 → 과업지시서 서식(안건·참석자·주요 논의·결정사항·기관별 요청사항·반영계획)의 회의록을 로컬 LLM이 작성하고 → 전사문·회의록이 로컬 RAG에 쌓여 출처가 표시된 답변으로 검색되며 → 회의 중 노트북 카메라로 현장 사진을 회의 기록에 붙일 수 있는 프로그램. **어떤 데이터도 노트북 밖으로 나가지 않는다.**

## 2. 하는 것 / 안 하는 것 (발표에서 먼저 말할 한 문장)
- 하는 것: 녹음 → 전사 → 회의록 초안 → 검색·질의 → 사진 첨부 → 회의록·관리대장 내보내기(MD/CSV/JSON)
- 안 하는 것: 보고서 집필(초안·근거 제시까지), 화자 **식별**(발화 구분과 역할 추정까지, 이름 확정은 서기가 검토 화면에서), 클라우드 전송(없음)

## 3. 구조 (단일 노트북)
```
브라우저(Edge --app 창)  ──HTTP/WS(127.0.0.1)──▶  FastAPI (Python, 127.0.0.1:8765)
  · MediaRecorder(마이크) 5~10초 청크 업로드          · faster-whisper (CPU int8, medium/small) 청크 전사
  · getUserMedia(카메라, 앞/뒤 선택) 사진 촬영         · Ollama: LLM(qwen2.5) 회의록 JSON · bge-m3 임베딩
  · 전사문 실시간 표시 / 회의록 검토·수정 / 질의       · 저장소: SQLite(meetings·segments·photos·minutes·qa)
                                                          + numpy 벡터스토어(1024d, 700자 청크) — 팩트온·미팅온 동일 규격
```
- 마이크·카메라를 **브라우저가 담당**하므로 장치 드라이버·권한 문제가 Python 쪽에 없다(sounddevice/OpenCV 미사용). 노트북 앞·뒤 카메라는 `enumerateDevices()`로 선택.
- 녹음은 청크(webm/opus) 단위로 서버에 쌓고, 서버는 청크가 오는 대로 전사해 WebSocket으로 자막처럼 밀어 준다(준실시간). 정지하면 전체 파일을 한 번 더 전사해 최종본으로 교체(청크 경계 잘림 보정).
- 원본 음성은 회의 폴더에 보존(옵션으로 전사 후 삭제 — 미팅온 원칙).

## 4. 화면 (좌측 회의 목록 · 우측 작업 영역, 상단 탭 4개)
1. **녹음** — 큰 녹음 버튼, 경과 시간, 입력 레벨 미터, 실시간 전사 스트림, 우측에 카메라 미리보기 + 촬영 버튼(앞/뒤 전환), 촬영한 사진 썸네일 타임라인.
2. **전사·회의록** — 좌: 발화 단위 전사문(시각·화자 라벨(추정)·본문, 인라인 수정) / 우: LLM 회의록 초안(요약·주요 논의·결정사항·회의결과·기관별 요청사항 표) + [회의록 생성] [승인] [내보내기].
3. **검색·질의** — 질문 입력 → 출처(회의명·일시·발화 시각) 인용 답변, 근거 청크 펼치기. 범위 선택(이 회의 / 전체 회의).
4. **회의 정보·사진** — 제목·관련기관·일시·장소·안건·참석자(화자 라벨 매핑용), 사진 갤러리(촬영 시각·메모), 관리대장 행 미리보기.
- 디자인: [회사명] 제품군 톤(미팅온 CSS 계보) — 차분한 차콜/화이트 + 포인트 1색, 시스템 폰트, 큰 상태 표시(녹음 중 빨간 점·전사 진행률·LLM 처리 중), 다크 배경의 녹음 화면. 모든 처리 상태를 화면에 문장으로 표시("1분 32초 녹음 · 전사 92% · 로컬 처리").

## 5. 데이터 모델 (SQLite `data/meeton_note.db`)
- meetings(id, title, org, kind, held_at, place, agenda, attendees, status, audio_path, created_at)
- segments(id, meeting_id, seq, t0, t1, text, speaker, speaker_src['cluster'|'llm'|'user'], is_final)
- photos(id, meeting_id, taken_at, path, note)
- minutes(id, meeting_id, version, summary, discussion, decisions, result_text, requests_json, engine, approved_at)
- qa_log(id, meeting_id nullable, question, answer, sources_json, engine, created_at)
- 벡터스토어 `data/rag/` : corpus.jsonl / embeddings.npy / meta.json (팩트온 규격, rel=`meeton-note/<id>_<title>.txt`)

## 6. 모델·성능 전략 (CPU 노트북 전제, 사양 확정 후 조정)
| 역할 | 기본 | 상향(GPU/32GB) | 하향(8GB) |
|---|---|---|---|
| STT | faster-whisper **medium int8** (한국어, vad_filter) | large-v3 fp16 (GPU) | small int8 |
| LLM | Ollama **qwen2.5:3b** (num_ctx 8k, temperature 0.2) | qwen2.5:7b / qwen3 | qwen2.5:1.5b |
| 임베딩 | Ollama **bge-m3** (1024d) | 동일 | 동일 |
| 화자 | whisper 세그먼트 + LLM 발화 구분·역할 추정("추정" 표기) | + resemblyzer 군집 | 동일 |
- 청크 전사는 5~10초 단위, medium int8은 4코어에서 대략 실시간의 1~1.5배 → 준실시간 자막은 약간 뒤따라옴. 시연은 1~2분 녹음.
- 모델은 전부 사전 다운로드(`models/` + Ollama). 발표장 인터넷 불필요.

## 7. 정직성 경계 (발표 멘트)
- "미팅온 엔진을 노트북 단독으로 구성한 시연판. 오늘 녹음·전사·회의록·검색이 이 노트북 안에서만 돈다."
- "화자는 발화 단위로 나누고 역할을 추정하며, 이름 확정은 서기가 한다." "실운영 중" 금지.
- 회의록은 초안이며 승인 절차를 거친다(미팅온과 동일). 관리대장 서식은 과업지시서 그대로(실시일·기관명·참석자·안건·회의결과·조치담당자·반영결과).
